# 生成

[English](generation.md) | **日本語**

[← README へ戻る](https://github.com/akitenkrad/rs-pxsmith/blob/main/README.ja.md)

`pxsmith gen prog` は言語モデルに L0 テキストを書かせ，それを読み取って lint に掛け，
blocking のルールが違反を報告した場合には，その指摘を返してもう一度依頼します．ここで使う検査器は
他の場面と同じ `pxsmith lint` であり，生成のために特別に書いたものは一つもありません．

```sh
export ANTHROPIC_API_KEY=...

pxsmith gen prog out/chest.px.toml --prompt "木の宝箱．正面から" \
    --palette 1a1c2c,566c86,8a6a4a,b13e53,f4f4f4 --size 16x16

pxsmith gen prog out/x.px.toml --prompt "宝箱" \
    --palette 1a1c2c,f4f4f4 --size 8x8 --dry-run   # 依頼を出すだけ．送らない
```

`--dry-run` は組み立てた依頼の本文をそのまま出力します．API キーはヘッダにしか含まれない
ため本文を出力しても漏れることはなく，キーを消費せずに送信内容を人が確認できる唯一の
手段になっています．

## モデルは色を作れない

L0 は自己完結した形式ではありません．パレットは外部の `.hex` ファイルへの参照であり，
本文には添字の文字しか記述できません．そこでツールが先に `.hex` を書き出し，モデルは
文字だけを書くという分担にしています．

これは制限というよりも保証です．「パレットにない色を出さない」という性質が検査ではなく
構造として成り立ち，モデルにはそもそもパレット外の色を表現する手段がありません．

## 何を検証していて，何をしていないか

作り直しのループが回るのはモデルの出力に対してであって，通信経路に対してではありません．
断り，応答の打ち切り，バックエンドの誤りが発生した場合は再試行せずそこで終了します．
同じ依頼を送れば同じ壁に当たるためです．ループが回るのは「読めなかった」場合と
「blocking の違反が出た」場合の 2 つだけであり，いずれも次の依頼に助言を加えることが
できます．

コマの列も検査の対象です．コマが 2 つ以上ある場合にはフレーム間の 6 ルールが適用され，
システムプロンプトはその内容を明記して渡します．知らせていない規則によって落とすのは
規則とは言えないためです．

## seed は無く，素性がその理由を記録する

採用したモデルは `temperature` も `top_p` も seed も受け付けません．したがって
「同じ依頼であれば同じ絵が得られる」という性質は成り立ちません．素性ファイルには，
嘘になる seed の欄を設ける代わりに，なぜその欄が存在しないのかを記述しています．
ビルドが再現するのはキャッシュと結果のコミットによるものです．詳しくは
[レシピ](recipes.ja.md)を参照してください．

素性には実際に応答したモデルも記録します．依頼したモデルとは限らないためです．肩代わり
(fallback) を有効にしているため別のモデルが応答することがあり，ツールは送信した名前を
書き写すのではなく，応答から読み取った名前を記録します．

## 外部呼び出しには門を設けている

生成の op はレシピから `--allow-generate` なしでは実行されないため，ビルドが利用者の
知らないうちに外部へ接続することはありません．
