# 生成

[English](generation.md) | **日本語**

[← README へ戻る](../README.ja.md)

`pxsmith gen prog` は言語モデルに L0 テキストを書かせ，読み取り，lint に掛け，
blocking なルールが鳴ったら**指摘を返してもう一度頼みます**．検査器はどこでも
使っている `pxsmith lint` そのもので，このために書いたものは 1 つもありません．

```sh
export ANTHROPIC_API_KEY=...

pxsmith gen prog out/chest.px.toml --prompt "木の宝箱．正面から" \
    --palette 1a1c2c,566c86,8a6a4a,b13e53,f4f4f4 --size 16x16

pxsmith gen prog out/x.px.toml --prompt "宝箱" \
    --palette 1a1c2c,f4f4f4 --size 8x8 --dry-run   # 依頼を出すだけ．送らない
```

`--dry-run` は組み立てた依頼の本文をそのまま出します．鍵はヘッダにしかないので
本文を出しても漏れません — **鍵を使わずに «送る側» を人が読める唯一の道**です．

## モデルは色を作れない

L0 は自己完結していません．パレットは外部の `.hex` への**参照**で，本文には
添字の文字しか書けません．そこで道具が先に `.hex` を書き，モデルは文字を書きます．

これは制限というより**保証**です．「パレットにない色を出さない」が検査ではなく
**構造として**成り立ちます — モデルには表現する手段がありません．

## 何を検証していて，何をしていないか

作り直しの輪が回るのは**モデルの出力**に対してであって，経路に対してではありません．
断り・応答の打ち切り・バックエンドの誤りは，再試行せずそこで終わります
（同じ依頼は同じ壁に当たるからです）．輪が回るのは「読めなかった」と
「blocking が鳴った」の 2 つだけで，どちらも次の依頼に助言を足せます．

**コマの列も検査します．** コマが 2 つ以上あるとフレーム間の 6 ルールが掛かり，
システムプロンプトはそれを**書いて渡します** — 知らせていない規則で落とすのは
規則ではありません．

## seed は無い．素性がその理由を書く

このモデルは `temperature` も `top_p` も seed も受け付けません．したがって
「同じ依頼なら同じ絵」は**成り立ちません**．素性ファイルには，嘘になる seed 欄を
置く代わりに**なぜ無いか**を書いてあります．ビルドが再現するのはキャッシュと，
結果をコミットすることによります（[レシピ](recipes.ja.md)）．

素性は**答えたモデル**も記録します — 頼んだモデルとは限りません．肩代わり
（fallback）を有効にしているので別のモデルが応えることがあり，道具は送った名前を
書き写すのではなく**応答から読み取った名前**を書きます．

## 意図的に書いていないもの

`pxsmith gen image` は**意図的に実装していません**．設計は格子が非一様な生成画像を
棄却しますが，拡散モデルがその条件をどれくらいの割合で満たすかはモデル依存で，
**上限が読めない**からです．誰かが後から «穴» として見つけ直すのではなく，
ここに書いておきます．

外部呼び出しには門があります．生成の op はレシピから `--allow-generate` 無しでは
走らないので，**ビルドが黙って外部へ出ることはありません**．
