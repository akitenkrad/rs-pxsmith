## 次にやること

### 1. $\varepsilon$ を画像の分散で正規化する案を測る

**実データ (自作レンダ 25 件) で，正解が分かっている 9 件を全部外した** (誤答 3 ・棄却 6) ．
誤答はすべて過大推定である ($\hat{s} = 10, 13, 14, 15$) ．

原因の見当は付いている — **画像全体の分散が 2.3 倍ちがう** (合成 0.105 / レンダ 0.045) ．
$\varepsilon$ は分散の絶対値に対する閾値なので，低コントラストの入力ではすべての $s$ が
楽に通り，「閾値を満たす最大の $s$」が大きい方へ流れる．信頼度の分母も画像分散なので，
こちらも尺度が変わる．

やること: $\varepsilon$ を $\bar{V}_{\mathrm{image}}$ で割った形を測り，**合成データの
成績を落とさずにレンダが通るか**を見る．通るなら閾値の持ち方が間違っていたことになる．
**測ってから直す** — これまで 3 回とも，先に実装していたら外れを掴んでいた．

### 1a. 実データの調達 (並行．素材待ち)

```sh
cargo run -p px-calib --release -- ingest <画像...>   # 正例に仕立てる
cargo run -p px-calib --release -- real               # 1 件ずつ並べる
```

| 区分 | 状態 |
| --- | --- |
| `render` | 済 (25 件．自作レンダ．同梱) |
| `ai-output` | 未．ChatGPT 出力 4 件は**格子が無く**正例にならない (負例候補として保留中) |
| `screenshot` | 未．配布素材 22 件を検討したが**格子が無く不採用** |

> [!warning] 「ドット絵風」は目視でも近似一致率でも判定できない
> 縮小表示ではブロックが並んで見えても，拡大すると縁が滑らかで境界が無いことがある．
> 隣接行の近似一致率は平坦な領域で 90% を超えるので**証拠にならない**．
> `ingest` の判定 (縁が境界へ集中しているか) を使うこと．**この誤りを 1 度踏んだ**．

正例を得るには，AI 出力をそのまま使うのではなく「縮小 → 既知の整数倍で拡大」の一手間が
要る．`ingest` がそれを行い，読めないものは理由付きで拒否する．
再配布できない素材は `testdata/grid-eval/real/local/` (追跡しない) へ置き，
入手元だけ `testdata/SOURCES.md` に記録する．

### 2. 検証セットに残っている 7 ポイント

マクロ平均 88.1% (完全一致 83.2% / 正棄却 93.0%) ．**所在は測ってある．**

| 格子あり 101 件 | 件数 |
| --- | --- |
| 正解 | 84 |
| 誤棄却 (信頼度不足) | 14 |
| 誤棄却 (検査で落ちた) | 2 |
| $s$ を外した | 1 |
| **位相だけ外した** | **0** |

位相は 1 件も外していない．$\hat{s}$ を外した 9 件のうち 6 件は**位相ずれ検査が真の
スケールを落として**おり，3 件は大きい $s$ に負けている (うち 2 件は勝った側で位相ずれ
検査が飛ばされていた — 候補の 23.3% で検査が働いていない) ．

> [!warning] 帯あたりの最小セル数を 1 にしてはいけない
> 評価データセットの成績は上がる (88.1% → 90.1%) が，**24 画素角のスプライトを 4 倍した
> 画像で真のスケールを落とす**．データセットの元絵が 16〜48 画素角なので，この失敗が
> 見えないだけである．小さい絵を入れてから測り直すこと．

### 3. 数値の校正 (1 ・2 の後)

決めるもの: $\varepsilon$ ・$\delta$ ・$\tau$ ・信頼度閾値 ・$w_L$ ・窓サイズ．
道具は揃っている．

```sh
cargo run -p px-calib --release -- gen      # 合成 500 件 (種 0 で再現する)
cargo run -p px-calib --release -- sweep    # 検証 300 件を掃引
cargo run -p px-calib --release -- report   # 指標と運転点
```

- **検証セットで決め，テストセットでの再調整はしない．** テストセットにはまだ
  1 度も触れていない
- 採点の定義は掃引 CSV からやり直せる (`Row::outcome` は行の内容から毎回求める) ．
  定義を変えても掃引はやり直さなくてよい
- **リサイズありの件の正解は「棄却」である** (整数の格子が存在しないため) ．
  $\mathrm{round}(s \cdot r)$ は正解にしない — 理由は `sweep::Outcome` の doc コメント
- 選ぶ指標は**マクロ平均**．素の正解率だと「ほぼ全部棄却」が勝つ (格子なしが 2/3)

## 落とし穴

実装中に踏んだもの．**同じ穴に落ちないこと．**

| 落とし穴 | 対処 |
| --- | --- |
| `Turn(chain)` をラン長の最小値で決める | 単発ジャギーを毎回見逃す．**G2 の曲率場から求める** (D60) |
| 単調区間を符号の反転だけで分ける | L 字の角が 1 本になる．**主軸に直交する歩みが 2 歩続いたら区切る** (D61) |
| `.hex` でアルファ 0 の色を飛ばす | 以降の添字が全部ずれる．**透明も 1 行として書く** |
| 局所格子推定で平坦な窓を投票させる | 「窓に収まる最大の $s$」が選ばれる．**信頼度 0 は投票しない** |
| `Srgb` へ変換してから成分を切り詰める | 色相がずれる．**`clip_to_gamut` で色相を保つ** |
| ディザ検出の入れ替わり率を 0.5 超に置く | ランダムディザを 1 件も拾えない (期待値が $2p(1-p) \le 0.5$) |
| 領域ラベリングを 8 連結にする | 市松が 1 領域になりディザ検出が壊れる．**4 連結** |
| 帯ごとの位相を帯の左端基準で測る | 帯ごとに違う物差しになり，本物の格子でもずれが出る．**画像の原点を基準に測る** |
| 帯の実験で再構成検査を切る ($\tau = 1$) | 過大推定が野放しになり，正解する件が nearest ばかりになる．問いは「今の検査が通した答えを選り分けられるか」である |
| 信頼度の対照群に小さい $s$ を入れる | $\bar{V}(s)$ は $s$ とともに単調に増えるので，最小値を必ず小さい $s$ が取りマージンが負に潰れる (D63) |
| 校正の成績を素の正解率で選ぶ | 「ほぼ全部棄却」が 1 位になる (格子なしの件が 2/3) ．**マクロ平均で選ぶ** |
| 試験の一時ファイルを全試験で共有する | `fs::write` が中身を空にする隙に別の試験が読み，稀に落ちる．**試験ごとにディレクトリを分ける** |

## 決まっている作法

- 日本語は読点 `，` 句点 `．`
- 閾値には**暫定である旨を doc コメントに書く**．根拠が無い数字を黙って置かない
- 決定論性の 3 規則 (設計書 6.15) を守る．同点には必ずタイブレークを付ける
- `testdata/` は CC0 原則．**MIT は著作権表示を同梱すれば受け入れる** (例外を
  `testdata/SOURCES.md` に明記済み) ．CC-BY / CC-BY-SA / GPL は除外
- このリポジトリの `.md` に「generated by Claude Code」フッタは付けない
  (Obsidian vault 側は付ける)
