# ジャギー検出の誤検出率

- 調査時期: M1a
- 関連: 設計書 6.4 / D32，実装計画書 R22，付録 C 要調査 #1
- 再現: `cargo test -p pxsmith-io --test jaggy_rate -- --nocapture`

## 問い

ラン長の谷検出が実データで誤検出しないか (手描きの意図的な凹凸を違反と判定しないか)．

## 途中で分かった設計上の落とし穴

設計書 6.4 は「例外は曲率符号が反転する点 $\mathrm{Turn}(chain)$ の 1 箇所のみ」と
規定する．これを**ラン長列の最小値**として実装すると，

```
runs = [3, 3, 1, 3]     谷は添字 2．内部の最小値も添字 2
```

となり，**単発のジャギーが毎回「反転点」として見逃される**．最も普通のジャギーが
まさにこの形なので，規則が丸ごと無効になる．

反転点はラン長列だけからは決まらない — 「凹凸が入れ替わったのか，単に凸凹して
いるのか」の区別が付かないためである．**G2 の曲率場から符号を読む**形に直した．
ラン $i$ の前後で曲率の符号が入れ替わっていれば反転点とみなす．

これは G1・G3 だけでは足りず G2 が要るということであり，**基盤を先に揃える方針
(判断 6) が正しかったことの実例**でもある．個別実装なら `smooth` の中で
この問題に気付かず出荷していた可能性が高い．

## 追記 (2026-08-15) — **真値のある場面で測った．誤検出は «ある» ・原因は数え上げ** (D163)

上の測定はすべて **正解ラベルが無い**．付録 C #1 が問うているのは
«手描きの**意図的な**凹凸を違反と判定しないか» であって件数ではないので，
実素材で何件鳴っても «くぼみが作者の意図か滑らせ損ねか» が誰にも分からない以上，
誤検出率にはならない (`by_shape` の分類は代理でしかない) ．

そこで**縁の凹凸が 1 つ残らず幾何で決まる絵**を作った — 円板と，有理数の傾きの
階段である．**ここに出た検出は，全件が定義から誤検出**になる．
測る口は `pxsmith-calib jaggy-truth`．

| 群 | 枚数 | ラン | 検出 | 率 |
| --- | ---: | ---: | ---: | ---: |
| 円板 | 38 | 2612 | 64 | **2.45%** |
| **階段 (短い走りが孤立)** | 10 | 339 | **95** | **28.02%** |
| 階段 (短い走りが隣接) | 10 | 385 | **0** | **0.00%** |
| 合計 | 58 | 3336 | 159 | 4.77% |

**そして `pxsmith smooth` は清書を 88 画素 ・17 / 58 枚 書き換える．** 鳴るだけなら
助言で済むが，`smooth` は画素を動かす — **正しく描いた線が壊れている**．

### どの傾きが鳴るかは閾値ではなく式で決まる

傾き $a / b$ の階段は，1 周期 ($x$ が $b$ 進む間) に走りが $a$ 本並ぶ．
長さは 2 種類しかなく，**長い走りが $b \bmod a$ 本 ・短い走りが $a - (b \bmod a)$ 本**
である．谷とは «両隣より短い走り» なので，**短い走りが 2 本続くと谷にならない**．
走りは可能なかぎり均等に散るので，短い走りが長い走りより多いときだけ隣り合う:

$$\text{谷ができる} \iff a - (b \bmod a) \leq b \bmod a \iff 2\,(b \bmod a) \geq a$$

**掃引しても動かない** — 閾値ではなく数え上げだからである (D92 と同じ側) ．
20 通りの傾きで式と実測が**全件一致**した (うち 8 通りは式を書いた後に足した
未知の組で，**予測が当たっている**) ．

| 傾き | $2(b \bmod a) \geq a$ | 実測 |
| --- | --- | --- |
| 1/2 ・1/3 ・1/4 ・1/5 | 偽 | 鳴らない |
| **2/3 ・2/5 ・2/7** | **真** | **鳴る** |
| 3/4 ・3/7 | 偽 | 鳴らない |
| **3/5 ・3/8** | **真** | **鳴る** |
| 4/5 ・4/9 ・5/6 | 偽 | 鳴らない |
| **4/7 ・4/11 ・5/8 ・5/9 ・5/14** | **真** | **鳴る** |

> [!note] **式を 1 度書き損ねた．** 最初は «短い走りが 1 周期に 1 本だけ»
> ($b \bmod a = a - 1$) と書いたが，5 / 8 は短い走りが 2 本あるのに鳴る —
> **1 本である必要は無く，隣り合わなければよい**．条件を 1 段強く書きすぎていた．

### 捕捉率 — 対照を置いた

誤検出率だけでは «何も鳴らさない道具» が満点を取る (D114 で «動かさない» を
対照に置いたのと同じ) ．負例は**設計書 6.4 が挙げる形そのもの**にした —
段の境目を 1 つ手前へ動かし，`[3,3,3]` を `[3,2,4]` にする．

**負例 84 件のうち実際に谷ができたのは 69 件で，そのうち 53 件を捕捉 (76.8%)．**

> [!warning] **負例の作り方をまた外した (この計画で 4 度目) ．**
> 最初は «縁の外へ 1 画素出っ張らせる» で作ったが，**あれは原理的に検出できない** —
> 出っ張りは向きの反転を作るので `split_monotone` がそこで区間を切り，
> `[1,3,3,3,…]` が `[1,3,3,2]` と `[3,3,3,…]` に割れて**どちらにも谷が残らない**．
> **谷を数える規則に «谷を作らない負例» を掛けて «捕捉 8%» と読むところだった．**
>
> 直したうえで，**各負例に谷ができたかを機械で数えて必ず併記する**ようにした
> (`defects_with_valley`) ．負例の作り方を目で確かめるのはもう 4 回失敗している．
>
> なお «出っ張りは拾えない» 自体が結果である — 87 件中 17 件しか捕捉しない．
> **ジャギー検出は «へこみ» の道具であって «出っ張り» は守備範囲外**である．

### 付録 C #1 の答え

**誤検出はする．** ただし «手描きの気まぐれ» ではなく，**正しく描いた
特定の傾きの直線**で起きる — そしてどの傾きかは式で決まるので，
**閾値を動かしても消えない**．

**直すなら «谷を数える» の手前** — 走りが 2 種類しか無くその並びが
傾きから説明できるなら，短い走りは幾何であって欠陥ではない，と読む余地がある．
ただしこれは D32 (谷検出を採る) の設計判断に触るので，**測っただけで止める**
(D92 «書いていないものを黙らない») ．

```sh
cargo run -p pxsmith-calib --release -- jaggy-truth   # 真値のある場面
cargo run -p pxsmith-calib --release -- jaggy         # 実素材 61 枚 (ラベル無し)
```

## 結論と限界

**M1a 時点の «検出率 0.1%» は弱い証拠だった** — 素材が Aseprite のテスト
スプライト (四角 ・点 ・文字) で «意図的な凹凸» を含まず，正解ラベルも無く，
測っていたのは頻度であって誤検出率ではなかった．

**2026-08-15 に真値のある場面で測り直して，付録 C #1 は閉じた** (上の追記) ．

| 問い | 答え |
| --- | --- |
| 意図的な凹凸を違反と判定するか | **する**．正しく描いた階段の 28.02% ・円板の 2.45% |
| どういうときに起きるか | **$2(b \bmod a) \geq a$ の傾き**．閾値ではなく数え上げ |
| 掃引で直るか | **直らない** |
| 実害はあるか | **ある**．`pxsmith smooth` が清書を 88 画素 ・17 / 58 枚 書き換える |
| 本物の欠陥は捕まえるか | **捕まえる**．谷ができた負例の 76.8% |

**残る限界**: «正しく描いた線» を円板と有理数の階段で代表させている．
手描きの絵にはこの 2 つに当てはまらない意図的な形もあるので，
**誤検出率の下限**として読むこと (この場面で鳴る以上，実素材でも鳴っている) ．

## 直線だけ守った — `pxsmith smooth` が正しい線を書き換えるのを止めた (2026-08-15 ・D169)

**R22 の扱いを決めた**: 検出器は触らず (ルール 8 は advisory なので助言のまま)，
**画素を動かす `pxsmith smooth` の側だけが手を引く**．D163 が «鳴るだけなら助言で済むが
`smooth` は画素を動かす» と書いた，その線引きをそのまま実装した形である．

### まず «どこが壊れているか» と «何が真偽を分けるか» を測った (D168)

| | 鳴った枚数 | 動いた画素 |
| --- | ---: | ---: |
| **円板** | 13 | **56** |
| 階段 | 21 | 28 |

**壊れているのは主に円板だった．** «傾きで説明できる» という条件は階段しか拾えない
ので，これだけでは 88 → 0 に届かない．

そして**谷の局所の形は偽と真をまったく分けない**:

| 深さ | 偽 (清書) | 真 (崩し) |
| ---: | ---: | ---: |
| 1 | 161 | 170 |
| 2 | 0 | 12 |

両隣の差 (偽 145 / 真 137 が差 0) も，単調区間の端からの距離も同じ広がりだった．
**3 つとも使えない** — 分けているのは谷ではなく，**周りの並びが幾何で説明できるか**
という区間全体の性質である．

### 判定は数え上げで書ける

一定の傾き $a/b$ の直線は，走りの長さが $\lfloor b/a \rfloor$ と
$\lceil b/a \rceil$ の 2 種類しか取らず，**並びができるだけ均等になる**
(Sturmian) ．この性質は再帰的で，«珍しい方の間に普通の方が何個あるか» を
数え直すと同じ条件になる．**閾値は 1 つも無い**
(`pxsmith_core::geom::runs::is_digital_straight`) ．

> [!note] **D32 とは向きが逆なので両立する．**
> D32 が退けたのは «理想 Bresenham 列との比較» を**検出器**にすることで，
> 理由は «意図的に描かれた曲線をすべて違反と判定する» ことだった．
> ここは**抑制**にしか使わない — «触らない» としか言わないので，
> **曲線を違反にする方向には決して働かない**．

**例外が広がりすぎない歯止めを 2 つ置いた**:

- **端の走りは落とす** — 切り取られた走りは短く出るだけで傾きの証拠にならない
- **1 度きりの値は模様と呼ばない** — `[3, 3, 2, 3]` は «2 種類が 1 違い» を
  満たすが 2 が 1 度しか出ない．**これは D80 が «最も普通のジャギー» として
  挙げた形**なので，ここを真にすると `smooth` が本物を直さなくなる

### 測った結果

| | 前 | 後 |
| --- | ---: | ---: |
| **清書での書き換え** | 88 画素 ・17 / 58 枚 | **60 画素 ・13 / 58 枚** |
| 負例の捕捉 | 53 / 69 (76.8%) | **53 / 69 (76.8%)** |
| 実素材で動かした画素 | 104 | **89** |
| 実素材で残るジャギー | 35 | **51** |

**階段の分 (28 画素) がちょうど消え，円板が残った．** 捕捉は動いていない．

実素材で残りが 16 件増えたのは，**それらが直線として説明できる区間に乗っていた**
からである — つまり `smooth` は実素材でも正しい線を書き換えていた．
収束 ・面積 ・blocking の不変条件はいずれも変わっていない．

> [!warning] **端から端まで通して 1 件出た．** 単体試験が緑になった後，
> `pxsmith lint` が «**`pxsmith smooth` で直せる**» と言っているのに smooth が触らない，
> という食い違いが残っていた．**助言は道具が実際にすることと合っていなければ
> ならない**ので，直線の谷では文言を変えた．
>
> **負例を 2 度続けて外した** (この計画で 5 度目 ・6 度目) ．
> `[3, 3, 1, 3, 3]` は深さ 2 で移動上限を超え，`[3, 3, 2, 3, 3]` はどちらへ
> 借りても谷が残る — **どちらも例外に届く前に止まっていた**．道具ではなく
> 試験が誤っていた．**«直る形» であることを先に確かめること．**

### 残っていること — 円板は «散発» ではなく «構造» だった (2026-08-15 に測った)

**円板 (60 画素 ・13 枚) は守れていない．** ただし中身を見たら，揺らぎではなく
**1 象限に 1 つずつ出る構造**だった — 鳴った円板はどれも**ちょうど 4 件**である．

r = 13 の円板 (中心 (15, 15)) で出た 4 件:

| 位置 | 中心からの相対 |
| --- | --- |
| (4, 9) | (−11, −6) |
| (9, 26) | (−6, +11) |
| (21, 4) | (+6, −11) |
| (26, 21) | (+11, +6) |

**90 度回転で移り合う 4 点**である．形はすべて **`[2, 1, 2]`** (走り 1 が両隣 2 より
短い) ．角度は約 28.6 度で **45 度ではない**ので八分円の境目ではなく，
**«走りが 2 の帯» から «走りが 1 の帯» へ移る継ぎ目**そのものである．

つまり円板の誤検出は，**傾きの違う 2 つの直線区間の継ぎ目**で起きている．

#### 形式的な道具はある — ただし直線のときほど安全ではない

**maximal digital straight segment 分解 (tangential cover)** が この構造を扱う．
増分的な直線認識器で区間を極大の直線分に分け，谷がその継ぎ目に乗っていて
**傾きが単調に変化している (= 凸弧)** なら幾何とみなす．
`is_digital_straight` (D169) はその 1 段目の非増分版にあたるので地続きである．

> [!warning] **直線の例外は «健全» だったが，凸弧の例外はそうならない．**
> 区間が厳密に digital straight line なら**定義上そこに直すべきものは無い** —
> 判断の余地が無かった．凸弧の判定は**弧が本当に凸であること**を要求するが，
> **実素材の絵は凸でないものが大半**である．そして **D168 で測ったとおり，
> 谷の局所の形では偽と真が分かれない** — 手描きの本物のジャギーも «傾きの継ぎ目»
> に見える．**«継ぎ目だから許す» は本物まで許す見込みがある．**

#### 次にやること — **実装より先に上限を測る**

«継ぎ目の谷を全部許したら» 負例 69 件の捕捉と実素材 61 枚がどうなるかを
**上限値として先に測る**．採れない結論なら実装せずに済む
(D169 で «測ってから決める» が実際に見立てを 2 つ覆したのと同じ理由) ．
